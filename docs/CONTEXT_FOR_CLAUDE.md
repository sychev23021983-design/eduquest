# Контекст проекта EduQuest для Claude

Читай этот файл первым в начале работы над уроками. Он заменяет память о прошлых чатах.

## Инфраструктура
- Репозиторий: `sychev23021983-design/eduquest` (GitHub)
- Сервер: `147.45.42.169`, Ubuntu 24.04, Docker, путь `/root/eduquest`
- Деплой всегда через: `cd /root/eduquest && git pull && docker compose down && docker compose build --no-cache && docker compose up -d`
  (нужна полная пересборка без кэша — иначе фронтенд не обновится)
- Стек: FastAPI + SQLite (backend/, модульная структура — см. «Структура backend» ниже),
  React + Vite (frontend/src)
- У Claude нет прямого доступа к самому серверу — только к GitHub. Все данные (программа, уроки)
  попадают в БД через сид-функции в `init_db()` (`backend/db.py`), которые выполняются при
  старте контейнера.

## Структура backend (после рефакторинга, 2026-07)
`backend/main.py` — теперь всего 32 строки: создание `FastAPI(lifespan=...)`, CORS,
`app.mount("/uploads", ...)`, `lifespan` (вызывает `db.init_db()`) и десять
`app.include_router(...)`. Вся логика (70 эндпоинтов) живёт в отдельных модулях:

| Файл | Что там |

| `backend/auth.py` | JWT: `make_token`, `get_role`, `require_parent`, `require_any`, `security`. |
| `backend/telegram_service.py` | `tg_send`/`tg_send_result`, `get_telegram_config`, `get_integrations`/`save_integrations`. |

### Как добавить новый эндпоинт
1. Найди подходящий файл в `backend/routers/` по теме (таблица выше) — если ни один не подходит
   по смыслу, заведи новый `backend/routers/<тема>.py` с `router = APIRouter(prefix="/api")` и
   зарегистрируй его в `main.py` через `app.include_router(...)`.
2. Если эндпоинту нужна новая Pydantic-модель — добавь её в подходящий `backend/models/*.py`
   (или новый файл, если тема новая) и импортируй в роутере.
3. `get_conn()` — из `db`, `require_parent`/`require_any` — из `auth`, `tg_send`/`tg_send_result` —
   из `telegram_service`.
4. Порядок регистрации внутри роутера важен для путей одинаковой длины сегментов (например,
   `/api/skills/all-active` должен быть объявлен раньше `/api/skills/{skill_id}`, иначе FastAPI
   примет `all-active` за `{skill_id}`).

## Архитектура данных
Класс → Предмет → Раздел → Тема → Урок.
- `sections` (раздел): grade, subject, title, order_index, intro (текст введения)
- `topics` (тема): section_id, title, order_index
- `lessons` (урок): topic_id, subject, grade, topic, context_theme, explanation,
  explanation_game, questions (JSON-массив MCQ), boss_task (JSON), coins_lesson, coins_boss

## Как добавляются данные (важно!)
Ручных форм создания/редактирования уроков и разделов через UI больше нет — их убрали специально.
Всё добавляется кодом в двух местах:
- Сам `LESSON_DICT`/`ARTICLE_DICT`/текст программы (`MATH_5_CURRICULUM` и т.п.) — константой в
  подходящем файле `backend/content/<subject>_content.py` (например, новый урок математики —
  в `math_content.py`).
- Вызов `seed_*` с этой константой — строкой в `init_db()` внутри `backend/db.py`.

1. Программа (разделы/темы) — через `seed_curriculum_if_empty()` + текстовый блок вида
   `**1. Раздел**` / `- **Тема:** описание`, либо через UI-импорт на странице «Программа»
   (парсер тот же, `parse_curriculum_text()`, обе функции в `backend/db.py`). Работает только
   на пустой БД (проверяет, что раздел ещё не создан).
2. Добавить тему в уже существующий (ранее засеянный) раздел — через
   `seed_topic_if_missing(conn, grade, subject, section_title, topic_title)`. Добавляет тему в
   конец раздела (order_index = максимальный + 1). Используется, когда нужно дописать тему
   (например, контрольную работу) в раздел, который уже был засеян раньше и `seed_curriculum_if_empty`
   для него больше не сработает.
3. Введение раздела — через `seed_section_intro_if_missing(conn, grade, subject, section_title, текст)`.
4. Урок — через `seed_lesson_if_missing(conn, grade, subject, section_title, topic_title, LESSON_DICT)`,
   где `LESSON_DICT` — константа, добавленная в `backend/content/<subject>_content.py`. Все вызовы
   `seed_*` добавляются в `init_db()` (`backend/db.py`), они идемпотентны (не дублируют при
   повторном деплое).
5. Перегенерировать (заменить содержимое) уже существующий урок — через
   `seed_lesson_regenerate(conn, grade, subject, section_title, topic_title, LESSON_DICT)`. В отличие от
   `seed_lesson_if_missing`, если у темы уже есть активный урок, функция обновляет его поля
   (`explanation`, `explanation_game`, `questions`, `boss_task`, `coins_*`) прямо в существующей строке —
   `id` урока не меняется, прогресс учеников по нему не теряется. Если урока ещё нет — ведёт себя как
   `seed_lesson_if_missing`. Вызов в `init_db()` идемпотентен: при каждом деплое просто перезаписывает
   урок тем же содержимым, если LESSON_DICT не менялся.

## Контрольные уроки (проверка знаний по разделу)
Раз в раздел — обычно последней темой — добавляется контрольный урок (`topic: "Контрольная
работа"`), который проверяет знания по всем темам раздела сразу. Формат — тот же LESSON_DICT,
но `questions` может быть длиннее (7–10 вопросов вместо обычных 5, по 1+ вопросу на каждую
пройденную тему), а `explanation_game` обычно обыгрывает сюжет как «финальный отчёт/проверку»
перед закрытием дела, а не новую улику. Такая тема добавляется в уже существующий раздел через
`seed_topic_if_missing()` (см. выше), а не через переиздание `MATH_5_CURRICULUM` (хотя строку в
`MATH_5_CURRICULUM` тоже стоит дописать — на случай полного пересева пустой БД).

Перед пушем ОБЯЗАТЕЛЬНО:
- `python3 -m py_compile backend/main.py backend/db.py backend/content/*.py` (или весь `backend/`,
  если трогал роутеры/модели: `find backend -name "*.py" | xargs python3 -m py_compile`)
- Прогнать `init_db()` на временной БД (см. предыдущие коммиты для примера теста через
  `ast.literal_eval` на структуре словаря урока и/или `fastapi.testclient.TestClient`)
- `cd frontend && npm run build` — если трогал фронтенд

## Формат урока (LESSON_DICT)
```python
{
    "topic": "...",                      # должно точно совпадать с названием темы в программе
    "context_theme": "detective",
    "explanation": "...",                # официальное объяснение, 1 абзац, без сюжета
    "explanation_game": "...",           # детективная история — см. раздел «Сюжет» ниже
    "questions": [                       # 5 штук, MCQ на 4 варианта
        {"text": "...", "options": ["...", "...", "...", "..."], "correct": 0,
         "hint": "...", "explanation": "..."}
    ],
    "boss_task": {"text": "...", "solution": "...", "hint1": "...", "hint2": "..."},
    "coins_lesson": 50-70,
    "coins_boss": 30-45,
}
```
Рендерится в `LessonPage.jsx` (тема «Дело детектива» — cork-board стиль, см. `detective-theme.css`).
`explanation_game` — один связный абзац (переносы строк схлопываются в HTML), не список.

## Сюжетная линия (чтобы не повторяться)
Сквозная история: ночью в Музей математики пробрался вор и украл цифры/математические
объекты — ребёнок расследует серию «дел».
- **Дело №1 (1.1 Цифры и натуральные числа):** кража цифр из музея. Раскрыты темы: цифра vs
  число, разряды (шкаф с полками), бесконечность чисел, число 0. Финал: код от сейфа
  987650 (наибольшее 6-значное без повторов, оканчивается на 0).
- **Дело №2 (1.2 Сравнение натуральных чисел):** сейф с кодом 987650 открыт, но пуст — вор
  обронил перепутанные бирки с числами экспонатов. Раскрыты темы: сравнение по количеству
  цифр, сравнение по разрядам слева направо (первый несовпадающий разряд решает всё),
  ловушка с ведущими нулями («099» = 99). Финал: второй сейф открывает число 5371
  (наибольшее 4-значное с разными цифрами, меньше 5372 и больше 5290) — стало ясно, что вор
  охотится за самыми большими числами в зале.
- **Дело №3 (1.3 Округление чисел):** размытая записка вора с суммой ущерба «примерно
  47 000» — точных цифр не разобрать. Раскрыты темы: правило «5 и больше — вверх, меньше 5 —
  вниз», округление с переносом через разряд (49999 → 50000, как одометр), какая именно
  цифра решает исход округления. Финал: третий сейф открывает наименьшее число 4650,
  которое одновременно округляется до 4700 (до сотен) и до 5000 (до тысяч).
- **Дело №4 (1.4 Делимость чисел):** вор раскладывал монеты ровными рядами — то, что не
  делилось без остатка, оставлял на месте. Раскрыты темы: делитель/кратное, признаки
  делимости на 2, 3, 5, 9, 10. Финал: четвёртый сейф открывает 4680 — наименьшее число
  больше 4650, которое делится сразу на 2, 3 и 5.
- **Дело №5 (1.5 Простые и составные числа):** связка карточек с числами на цепочках и
  записка «раздели их на два лагеря». Раскрыты темы: простое число (ровно два делителя),
  составное число, разложение на простые множители, особый статус числа 1 (не простое и не
  составное). Финал: пятый сейф открывает 12 — наименьшее составное число ровно с шестью
  делителями, в разложении которого есть и 2, и 3.
- **Дело №6 (1.6 НОД и НОК), финал раздела «Натуральные числа»:** вор пойман с поличным, но
  сигнализация рассинхронизирована — один механизм тикает каждые 18 секунд, другой каждые
  24. Раскрыты темы: НОД (общие множители в наименьшей степени), НОК (все множители в
  наибольшей степени), формула НОК = (a×b)÷НОД, взаимно простые числа. Финал: сигнализация
  срабатывает одновременно через 72 секунды (НОК(18,24)) — дверь музея захлопывается за
  вором, дело о краже чисел закрыто. Раздел «1. Натуральные числа» пройден полностью.
- **Контрольная работа (после 1.6, перед архивом):** старший инспектор требует итоговый отчёт по
  всем шести делам раздела, прежде чем дело уйдёт в архив — 8 заданий на все темы раздела
  (натуральный ряд, запись чисел, сравнение, округление, делимость, разложение на простые
  множители, НОД, НОК) плюс boss-задача на комплекты сувениров (НОД(108,144)=36 наборов, по 3
  значка и 4 карточки). Финал: инспектор ставит печать «дело закрыто», намекая на «более
  интересный сюрприз» в архиве — прямая подводка к следующему делу (архив/гроссбух).

**Новая арка — «Архив вора» (раздел «2. Действия с натуральными числами»):** вор пойман, но у
него найден зашифрованный гроссбух со старыми делами. Каждый урок — шаг по цепочке улик от
одного тайника к другому.
- **Дело №7 (2.1 Сложение и вычитание):** колонка сумм в гроссбухе, одно слагаемое залито
  чернилами. Раскрыты темы: переместительное свойство сложения, сочетательное свойство
  (группировка ради круглых чисел), вычитание числа из суммы через один из компонентов. Финал:
  восстановленное число 113 — номер страницы с ключом от потайного ящика.
- **Дело №8 (2.2 Умножение и деление):** план склада-сетки (24×18 полок), полка с остатком по
  описи. Раскрыты темы: распределительное свойство умножения, деление нацело и деление с
  остатком (a = b×q + r). Финал: вычисление 45×16÷120 = 6 — номер ряда с каменной шкатулкой.
- **Дело №9 (2.3 Степень числа):** шкатулка-куб со стороной 6 см и квадратная плитка со
  стороной 9 см. Раскрыты темы: степень с натуральным показателем, квадрат и куб числа, объём
  куба. Финал: незаконченная формула на плитке (2³+5²×2 = 58) — вор не успел её досчитать.
- **Дело №10 (2.4 Порядок действий), финал раздела:** выражение (216−81)÷27+4×2³ = 37 —
  последний код архива. Раскрыты темы: порядок выполнения действий (скобки → степень →
  умножение/деление слева направо → сложение/вычитание). Финал: тайник со стопкой блокнотов —
  намёк, что у вора были «ученики» и расследование продолжится дальше. Раздел «2. Действия с
  натуральными числами» пройден полностью (4/4).
- **Контрольная работа (после 2.4, перед тайником с блокнотами):** старший инспектор снова
  требует отчёт — 8 заданий на все темы раздела (свойства сложения, распределительное свойство,
  деление с остатком, степень числа, порядок действий) плюс boss-задача с первым появлением
  буквенного выражения (9k+10m, при k=8, m=12 → 192) — приписка не рукой вора, прямая подводка к
  находке блокнотов учеников.

**Новая арка — «Шифр учеников» (раздел «3. Выражения и уравнения»):** почерк в найденных
блокнотах отличается от почерка вора — это его «ученики», зашифровавшие свои дела буквами и
уравнениями вместо чисел.
- **Дело №11 (3.1 Числовые и буквенные выражения):** запись «3a+15» с пометкой-загадкой на
  полях. Раскрыты темы: буквенное и числовое выражение, подстановка значения переменной, порядок
  действий при вычислении. Финал: a=7, значение выражения 36 — номер следующей страницы.
- **Дело №12 (3.2 Уравнения):** на странице 36 — уравнение x−18=47 с пометкой «здесь будет
  следующая встреча». Раскрыты темы: понятие уравнения и корня уравнения, зависимости между
  компонентами действий (сложение/вычитание/умножение/деление). Финал: x=65 — номер дома, куда
  ведёт след.
- **Дело №13 (3.3 Формулы), финал раздела:** у дома 65 — погоня к вокзалу. Раскрыты темы:
  формула пути s=v×t и обратные к ней (нахождение скорости, нахождение времени). Финал: детектив
  на автобусе (40 км/ч, 9 минут) обгоняет ученика на самокате (15 км/ч, 24 минуты) и перехватывает
  его на перроне до отправления поезда. Раздел «3. Выражения и уравнения» пройден полностью (3/3),
  а на перроне находится ещё один блокнот с тем же почерком — намёк, что учеников у вора больше
  одного.
- **Контрольная работа (после 3.3, блокнот с перрона):** инспектор проверяет знания по всему
  разделу, прежде чем открыть найденный на перроне блокнот — 10 заданий (буквенные/числовые
  выражения, составление выражений по условию, подстановка значений, простые и составные
  уравнения по алгоритму «выдели последнее действие», формулы пути и периметра) плюс boss-задача
  на составление уравнения (два псевдонима «Тень» и «Эхо», жетоны, уравнение 4x−18=x, x=6 у «Эха»,

## Познавательные материалы (статьи, без контроля знаний)
Отдельная от уроков сущность: `articles` (subject, grade, title, summary, cover_image, blocks,
manually_edited). Добавляются через `seed_article_if_missing()` (не трогает существующую статью)
или `seed_article_upsert()` (обновляет содержимое, если статья уже есть — НО только если её
ещё не редактировали через панель родителя: как только родитель сохраняет статью через
`ArticleEditor` — эндпоинты `POST/PUT /api/articles` — выставляется `manually_edited=1`, и
`seed_article_upsert()` больше никогда не трогает эту статью при следующих деплоях). Обе функции
идемпотентны, вызываются в `init_db()`, как и уроки.
**Баг, который это исправляет (найден и закрыт 2026-07):** раньше `seed_article_upsert()`
безусловно перезаписывала `cover_image`/`blocks` при каждом перезапуске контейнера — то есть
любая картинка/обложка, загруженная родителем через панель, откатывалась назад к исходному
варианту из кода при следующем деплое. Если раньше (до этого фикса) родитель уже успел загрузить
кастомную обложку к одной из 10 «зашитых» статей — она могла быть затёрта один последний раз при
деплое этого фикса (потому что `manually_edited` стартует с 0 у уже существующих строк); начиная
с этого деплоя — больше не будет.
**Второй баг (там же):** загрузка обложки в `ArticleEditor` раньше только заполняла слот в
`site_settings`, а само поле `cover_image` статьи сохранялось лишь при отдельном нажатии кнопки
«💾 Сохранить» — если родитель загружал картинку и сразу перезагружал страницу, не нажав
«Сохранить», обложка «слетала». Теперь для уже существующей статьи (`!isNew`) обложка сохраняется
в саму статью автоматически сразу после загрузки файла, без ожидания отдельного клика.
**Третий баг (найден и закрыт позже, тоже в этих двух функциях):** проверка «уже существует?»
искала строку только среди активных (`WHERE ... AND active=1`) — если родитель удалял одну из
10 «зашитых» статей через панель (`DELETE /api/articles/{id}` делает мягкое удаление,
`active=0`), то при следующем деплое `seed_article_if_missing`/`seed_article_upsert` не находили
такую строку (она же неактивна) и создавали её заново — удалённая статья «воскресала». Исправлено:
проверка теперь ищет строку с этим subject+title вообще без фильтра по `active` — если она
существует (даже удалённая), новую копию не создаём и не трогаем. Проверено воспроизведением
сценария «удалить → повторный init_db()» на тестовой БД до/после фикса.

**Диагностика удалённых материалов (добавлена, когда возник спор «удалил, а материал всё равно
где-то виден»):** обычное удаление — мягкое (`active=0`), строка остаётся в БД. Чтобы можно было
проверить, что удаление реально сработало (а не показалось, или удалили не ту запись), на
странице списка материалов (`/parent/materials`) под группами категорий есть выпадающая секция
«🗑 Удалённые материалы» — показывает все строки с `active=0` через
`GET /api/articles/deleted/list`, с кнопками «♻️ Восстановить» (`POST /api/articles/{id}/restore`)
и «🗑️ Убрать навсегда» (`DELETE /api/articles/{id}/purge` — жёсткое удаление строки из БД, в
отличие от обычного DELETE). Если материал, который «не удаляется», не находится ни в основном
списке, ни в этой секции — значит на самом деле удаляли другую запись/дубликат, и нужно искать
его отдельно (например, через `GET /api/articles/{id}` по конкретному id, если он известен). Для
этого на странице списка есть поле поиска — фильтрует по названию сразу во всех категориях,
включая раздел «Удалённые», и автоматически разворачивает совпадающие группы.

**Важный нюанс про purge и «зашитые» статьи:** кнопка «Убрать навсегда» (purge, жёсткое удаление
строки) для одного из 10 материалов, перечисленных в вызовах `seed_article_upsert()` в `init_db()`,
не помогает избавиться от материала навсегда — наоборот, гарантирует, что он пересоздастся заново
при следующем деплое, потому что seed-функция не может отличить «строки никогда не было» от
«строку стёрли навсегда». Единственный надёжный способ навсегда убрать один из этих 10
материалов — убрать соответствующий вызов `seed_article_upsert(...)` из `init_db()` в коде (как
сделано для «Почему идёт дождь?» и «Почему птицы летают» — родитель попросил их убрать навсегда,
вызовы удалены из кода, строки `ARTICLE_WHY_RAIN`/`ARTICLE_BIRDS_FLY` оставлены в файле, просто
больше не вызываются). Обычное (мягкое) удаление через кнопку 🗑️ в списке безопасно и навсегда
для этих материалов уже само по себе (см. третий баг выше) — purge нужен только для дублей и
мусорных записей, которых в коде-сидинге вообще нет.

Формат `blocks` (JSON-массив) — см. `ArticlePage.jsx`, `Block()`: поддерживаемые типы —
`heading`, `subheading`, `paragraph`, `callout`, `flow`, `list`, `checklist`, `experiment`
(title/materials/steps/result), `question`, `image` (`url` или `slot` — если картинки нет,
показывается плейсхолдер, ничего не ломается). Картинки по `slot` (внутри текста статьи, не
обложка) сохраняются в `site_settings` сразу при загрузке файла и не зависят от кнопки
«Сохранить» — но сам блок `{"type":"image","slot":"..."}", ссылающийся на этот slot, должен быть
уже сохранён в `blocks` статьи (обычным нажатием «Сохранить»), иначе после перезагрузки страницы
он просто не отрисуется (файл при этом не потеряется, просто останется без блока-ссылки на него).
Каждый `heading` начинает новый слайд на фронтенде. Пиши материал живым, увлекательным языком для
ребёнка 10-11 лет, с примерами и вопросами на подумать — здесь не нужен детективный сюжет уроков,
это отдельный жанр (объяснительная статья).

**Важно:** список категорий материалов — не текстовый файл, а два захардкоженных словаря, которые
обязательно нужно держать в синхроне при добавлении новой категории:
- `MATERIAL_SUBJECTS` в `backend/config.py` (ключ → русское название; ключи в `articles.subject`,
  которых нет в этом словаре, вообще не покажутся на странице «Материалы» — там строгий перебор
  по словарю, не по фактическим данным в БД).
- `MATERIAL_SUBJ` + `MATERIAL_SUBJ_ICON` в `frontend/src/materialSubjects.js` (русское название +

## Тон и стиль
- Обращение на «ты», доброжелательно, без сюсюканья (ребёнку 10-11 лет)
- В вопросах — конкретика, не абстракция; подсказки должны реально помогать, а не дублировать ответ
- boss_task — на 1 логический шаг сложнее вопросов, с двумя подсказками по нарастающей
- Не использовать чужие товарные знаки/персонажей (Roblox, Minecraft и т.п.) в текстах и описаниях UI

## Конвенции генерации заданий (обязательно при каждой генерации урока)

### Сложность заданий
- Задания НЕ должны дословно повторять примеры из `explanation` или `explanation_game` — используй
  другие числа, контексты, формулировки. Ребёнок должен **применить** правило, а не узнать
  готовый ответ из только что прочитанного текста.
- Дистракторы (неправильные варианты) должны быть **правдоподобными** — это типичные ошибки по
  теме (перепутал знак, забыл перенос разряда, применил не то правило), а не случайный мусор.
  Ребёнок, который не понял тему, должен «клюнуть» на дистрактор.
- Сложность 5 вопросов внутри урока должна **нарастать**: первые 1–2 — прямое применение правила,
  3–4 — чуть сложнее (два шага, нестандартный контекст), 5-й — на грани boss_task.

### Перемешивание позиции правильного ответа
- Для каждого вопроса в `questions`: сначала сформулируй правильный ответ и 3 дистрактора, затем
  **случайно перемешай** их порядок в массиве `options` и выставь `correct` на реальную позицию
  правильного ответа (0–3).
- Правильный ответ **НЕ должен** всегда стоять на одной и той же позиции. По 5 вопросам урока
  правильные ответы должны оказаться на разных индексах (например: 2, 0, 3, 1, 2 — а не 0, 0, 0, 0, 0).
- Перед финальной выдачей урока — проверь себя: если `correct` во всех вопросах одинаковый,
  перемешай заново.

### Финальное задание (boss_task) не повторяет первый экран
- `boss_task` проверяет тот же навык, что и задания урока, но с **другими данными/контекстом**.
- Условие, числа и сюжетная обёртка boss_task **НЕ должны** совпадать с условием первого вопроса
  из `questions[0]` или с примерами из `explanation`/`explanation_game`.
- Если первый вопрос был «сравни 4827 и 4872», boss_task должен использовать другие числа и,
  желательно, другую ситуацию (например, найти наибольшее число с ограничениями, а не просто
  сравнить два числа).

### Чек-лист перед выдачей LESSON_DICT
1. ✅ Числа в заданиях отличаются от примеров в `explanation` и `explanation_game`
2. ✅ Позиции правильных ответов (`correct`) разнообразны по 5 вопросам (не все на одном индексе)
3. ✅ Дистракторы — это правдоподобные ошибки, а не случайные числа
4. ✅ `boss_task` не дублирует условие `questions[0]`
5. ✅ `boss_task.answer` — одно финальное число/слово (см. «Баг проверки финального задания» ниже)
6. ✅ Сложность нарастает от вопроса 1 к вопросу 5

## Баг проверки финального задания (найден и закрыт 2026-07)
`_check_boss_answer()` требует, чтобы каждое число из поля `answer` встречалось в ответе
ребёнка как отдельный "токен" (не внутри другого числа). Если `answer` записан как
"промежуточный результат, итоговый код" (например, было `"5 целых 1/6, код 516"` в уроке
«Виды дробей», Дело №15) — цифры 5, 1, 6 "растворяются" внутри 516, и ребёнок, правильно
называющий только итоговый код 516, получал "ответ неверен" и не получал монеты за финальное
задание. Исправлено двумя способами:
1. В данных — `answer` упрощён до `"516"` (как и во всех остальных уроках, где answer — это
   просто итоговое число/код, без служебного текста). Обновлено через `seed_lesson_regenerate`
   (лесен уже был сыгран, если бы использовали `seed_lesson_if_missing` — фикс бы не применился
   к существующей строке).
2. В самой функции `_check_boss_answer()` — добавлен fallback: если самое длинное число эталона
   само присутствует в ответе как отдельное число, а все остальные числа эталона целиком
   состоят из его цифр (т.е. являются его частью), ответ засчитывается — на случай, если такой
   паттерн (итоговое число, содержащее цифры промежуточного) появится в `answer` других уроков
   в будущем.
При добавлении новых `boss_task` — не указывать в `answer` описательный текст с несколькими
числами, где одно число составлено из цифр другого; писать туда только то финальное
число/слово, которое реально попросили назвать в тексте задания.

## Работа над ошибками → дополнительные уроки закрепления (2026-07)
В кабинете родителя (вкладки «Аналитика» → «⚠️ Слабые места» и «Ошибки» → «По темам») у каждой
слабой темы есть кнопка «📋 Собрать для Claude». По клику `GET /api/lessons/{id}/reinforcement-prompt`
(только для родителя) собирает по уроку: предмет/класс/раздел, точность и число попыток
(`progress`), до 15 последних конкретных ошибок (`mistakes`: вопрос/выбранный/правильный ответ), и
формирует готовый текстовый запрос с инструкцией добавить урок «Закрепление: <тема>» тем же
способом, что и обычные уроки — `seed_topic_if_missing` + `seed_lesson_if_missing`, в конец
раздела, с другими числами/примерами, но тем же навыком. Текст показывается в модалке с кнопкой
«Скопировать» — родитель вставляет его в чат с Claude, а не вводит контент урока сам.
**Важно:** это осознанно НЕ полная автоматизация (backend не вызывает Claude API сам) — контент
уроков в проекте принципиально пишется кодом при участии Claude в чате (см. «Как добавляются
данные» в начале файла), это сохраняет контроль над качеством, сюжетной линией и форматом
LESSON_DICT. Если попросят добавить такой урок «Закрепление: ...» — он ничем не отличается от
обычного урока по структуре/сидингу, просто с пометкой «Закрепление:» в названии темы и с другими
конкретными числами, нацеленными на те же ошибки, что перечислены в промпте.


1. **Выбор количества материалов при отправке на изучение.** Backend (`MaterialAssignmentIn.count`,
   `POST /api/materials/assignments`) уже поддерживал параметр `count` (клэмп 1–10) — фронтенд
   (`SendAssignmentPanel` в `MaterialAssignmentTools.jsx`) жёстко слал `count: 3`. Добавлено поле
   ввода «Количество материалов» рядом с наградой.
2. **Формат Telegram-сообщения.** Темы теперь каждая с новой строки (с маркером 🔹), добавлены
   дополнительные эмодзи по тексту сообщения. Собирается в `create_material_assignment()`.
3. **401 "Invalid token" на весь экран.** Раньше при просроченном/битом JWT (`get_role()` кидает 401
   "Invalid token") любая страница (включая `/materials/assignment/:id`, на которую ссылается
   Telegram-сообщение) показывала это сырым текстом ошибки вместо повторного входа — типичный
   сценарий: ребёнок открывает ссылку с телефона, на котором токен уже протух или отсутствует.
   Исправлено в `api.js`: при HTTP 401 от `req()`/`upload()` локальный токен стирается
   (`localStorage.removeItem('eq_token'/'eq_role')`) и происходит редирект на
   `/login?next=<текущий путь>`. `Login.jsx` после успешного входа возвращает на `next`, если он
   есть, а не всегда на `/` или `/parent`. Guard в `App.jsx` не менялся — он и раньше правильно
   редиректил на `/login`, когда токена не было вообще (это отдельный случай от "токен есть, но
   невалиден").
4. **Звуки правильного/неправильного ответа.** Добавлены слоты `sound_correct`/`sound_wrong` в
   `DEFAULT_SETTINGS`, `SettingsIn` и `POST /api/settings/upload` (тот же эндпоинт, что и картинки
   интерфейса — определяет по имени слота, что для `sound_*` разрешены расширения
   mp3/wav/ogg/m4a вместо png/jpg/gif/webp/svg/ico). Загружаются в `/parent/settings` → новая
   карточка «Звуки ответов» (компонент `SoundUploadRow`). Проигрываются в `LessonPage.jsx`:
   правильный звук — при верном ответе на MCQ-вопрос улики и при верном финальном (boss) ответе;
   неправильный — при неверном варианте улики и при неверном финальном ответе. Если звук не
   загружен — ничего не проигрывается (как и раньше, тихо).
5. **Баг: финальное задание не засчитывалось ни при каком ответе (найден и закрыт 2026-07,
   обнаружен на уроке «Порядок действий», ответ «37»).** Причина — в БД у части уроков, засеянных
   ещё до того, как поле `answer` стало обязательной частью схемы `boss_task` в коде, это поле в
   сохранённом JSON отсутствовало вовсе (у самого урока в коде `answer` есть и всегда было "37" —
   несовпадение чисто в исторических данных БД, `seed_lesson_if_missing` не трогает уже
   существующие строки). Из-за этого `_check_boss_answer()` получал `expected=None` и
   безусловно возвращал `False`, независимо от того, что вводил ребёнок. Исправлено миграцией
   `backfill_missing_boss_answers()` (вызывается в конце `init_db()` при каждом старте): строит
   `{topic: answer}` из всех LESSON_DICT-констант модуля (`_lesson_answer_map()`) и для каждого
   активного урока, у которого в сохранённом `boss_task` нет `answer`, патчит только это поле —
   `text/solution/hint1/hint2` и id урока (а значит и прогресс/история попыток) не трогаются.
   Идемпотентно — на уроках, где `answer` уже есть, ничего не меняет. Если в будущем всплывёт
   похожий симптом («любой ответ неверен») на другом уроке — сначала проверить именно это (через
   `GET /api/lessons/{id}` или редактор урока — есть ли вообще ключ `answer` в `boss_task`), а не
   сразу чинить `_check_boss_answer()`.

# Предмет: Русский язык, 5 класс

Второй предмет курса (после математики). Архитектура данных, формат `LESSON_DICT`, способ
добавления уроков (`seed_lesson_if_missing`/`seed_lesson_regenerate` через `init_db()`),
конвенции генерации заданий (сложность, перемешивание позиций правильного ответа, чек-лист перед
выдачей) — **те же самые**, что описаны выше для математики; здесь фиксируются только отличия и
специфика самого предмета.

## Баланс «правило vs практика»
Договорённость (2026-07): для орфографии и пунктуации (§ в разделах «Синтаксис и пунктуация»,
«Орфография») вопросы почти целиком прикладные — вставить букву/расставить знаки/найти ошибку на
новом материале, а не пересказать формулировку правила. Для более понятийных тем («Культура устной
и письменной речи», «Речевая ситуация. Стили речи», «Текст») — 1-2 вопроса на понимание термина,
но большинство всё равно на анализ конкретного примера («определи стиль этого отрывка», а не «что
такое публицистический стиль»). `explanation` в любом случае короткий (правило по существу, без
сюжета), а весь сюжет — в `explanation_game`, как и в математике.

## Программа взята из
Учебник «Русский язык, 5 класс» в двух частях — структура и нумерация § сохранены из исходного
оглавления пользователя (см. `RUSSIAN_5_CURRICULUM` в `backend/content/russian_content.py`).
Нумерация § **начинается
заново в каждой из двух частей** — это не ошибка (в частях 1 и 2 есть, например, «Фонетика» и
«Фонетика (продолжение)» с параграфами § 1, § 2 в обеих — они в разных разделах, конфликта нет,
т.к. уникальность темы в БД проверяется в рамках раздела, а не глобально).

## Сюжет: «Вечерний вестник»
Городская газета «Вечерний вестник» была закрыта 40 лет назад — пожар повредил архив редакции.
Сейчас здание восстанавливают, и последний живой сотрудник старой редакции, пожилой редактор
**Архип Кузьмич**, ищет помощника, чтобы разобрать уцелевший архив и подготовить юбилейный
выпуск — не «с нуля», а из восстановленных материалов разных лет. Герой — ребёнок 10-11 лет
(отдельный персонаж, не тот же, что в математике), которого Архип Кузьмич берёт в помощники на
лето. Каждый раздел курса — это свой этап работы редакции над архивом:
- **Повторение изученного в начальных классах** — герой проходит что-то вроде вступительного
  испытания: Архип Кузьмич проверяет базовые навыки, прежде чем пустить в архив.
- **Культура устной и письменной речи** — герой учится общаться с посетителями редакции и писать
  грамотные записки/объявления.
- **Речевая ситуация. Стили речи** — герою поручают готовить материалы в разные рубрики газеты
  (новости, официальные объявления, очерки), и он учится различать стили.
- **Синтаксис и пунктуация** — самый большой этап: восстановление старых статей, где пожар и вода
  испортили часть текста (не хватает знаков препинания, размыты границы предложений).
- **Текст** — герою нужно из разрозненных, перепутанных абзацев старых черновиков собрать цельные
  статьи.
- **Фонетика / Фонетика (продолжение)** — Архип Кузьмич затевает выпуск радиоприложения к газете
  (дикторский текст), для которого важны ударения и произношение.
- **Орфография** — самый долгий этап: постепенное восстановление сильно повреждённых огнём и водой
  страниц архива, буква за буквой, по разным типам повреждений/орфограмм.
- **Лексика** — в архиве попадаются совсем старые выпуски с устаревшими словами и словами из
  профессионального жаргона наборщиков — герой учится понимать и объяснять читателям такие слова
  (это же прямая подводка к «Устаревшие слова. Неологизмы»).
- **Повторение изученного в 5-м классе** — финал: подготовка юбилейного выпуска к печати, тема и
  сюжет финального урока будут определены при генерации (аналог «Итогового экзамена» в математике).

Конкретные детали случаев (что именно повреждено, какие числа/примеры, какой финал) будут
придумываться и дописываться сюда по мере генерации каждого урока — так же, как в «Сюжетной линии»
математики выше. Здесь пока только общая канва, чтобы не расходиться в тоне и не повторяться.

**Раздел 1 «Повторение изученного в начальных классах» — вступительное испытание Архипа Кузьмича:**
прежде чем пустить героя в архив, редактор проверяет пять базовых навыков подряд, одним визитом —
не отдельная арка, а разминка перед основным сюжетом.
- **§ 1. Текст:** карточки архива вперемешку со случайными обрывками фраз — нужно отличить
  настоящий связный текст (тема + основная мысль + связь по смыслу) от бессвязного набора
  предложений, а также подобрать точный заголовок. Финал: из 5 карточек в стопке архива только
  3 оказываются настоящим текстом (объединены темой восстановления архива к юбилею).
- **§ 2. Словосочетание. Предложение:** тетрадь старого корректора с пометками об ошибках молодых
  журналистов — нужно различать словосочетание/предложение и находить грамматическую основу.
  Финал: в предложении «Вечерняя типография наконец после долгого простоя вновь застучала
  печатными машинами» грамматическая основа — «типография застучала» (2 слова).
- **§ 3. Состав слова. Орфограмма:** картотека наборщиков с разбором слов на части (корень,
  приставка, суффикс, окончание) и понятием орфограммы. Финал: слово «пришкольный» состоит из
  4 значимых частей (при- + школь- + -н- + -ый).
- **§ 4. Правописание:** размытые от воды бланки — восстановление базовых орфограмм начальной
  школы (жи-ши, ча-ща, безударные гласные, парные согласные). Финал: восстановленное слово
  «сторожил» (проверочное — «сторож»).
- **§ 5. Части речи, финал раздела:** картотечный ящик слов без системы — нужно разложить их на
  самостоятельные и служебные части речи. Финал: в предложении «Три опытных наборщика молча
  работали в цехе» — 6 самостоятельных частей речи (предлог «в» не считается). Архип Кузьмич,
  довольный проверкой, зачисляет героя помощником и вручает ключ от архива — переход к разделу
  «2. Культура устной и письменной речи» (герой начинает общаться с посетителями редакции).

**Раздел 2 «Культура устной и письменной речи» — приёмная редакции:** героя сажают за стол
дежурного принимать посетителей и разбирать черновики молодых журналистов — один день, семь
последовательных случаев, каждый на свою тему культуры речи.
- **§ 6. Язык и речь:** первый день, первый посетитель — герой учится различать общий язык и
  индивидуальную речь, три функции языка (коммуникативная, мыслеформирующая, накопительная).
  Финал: из 4 фраз Архипа Кузьмича только 2 иллюстрируют именно «речь» конкретного человека.
- **§ 7. Культура устной и письменной речи. Нормы литературного языка:** черновик корреспондента
  с ошибками «как получится» — вводится понятие языковой нормы. Финал: из 4 фраз черновика норма
  нарушена в 2 («ихний» вместо «их», «ложила» вместо «клала»).
- **§ 8. Произносительная, орфографическая, словообразовательная нормы:** визит диктора местного
  радио (задел на будущее радиоприложение к газете, см. «Фонетика» ниже) — разбор ударений и
  выдуманных слов. Финал: из 4 слов с ударением («звонИт», «тОрты», «красИвее», «свеклА») верно
  указано 3, ошибка — «свеклА» вместо «свЁкла».
- **§ 9. Морфологическая, синтаксическая, пунктуационная нормы:** письмо-жалоба читателя с
  ошибками сразу трёх видов. Финал: из 4 фраз письма норма нарушена в 2 («согласно приказа» вместо
  «приказу», «много помидор» вместо «помидоров»).
- **§ 10. Качества речи. Точность и логичность речи:** черновик анонса юбилейного номера,
  расплывчатый и нелогичный. Финал: из 4 предложений анонса точность/логичность нарушена в 2
  (логический круг «газета — газета», посторонняя мысль про кота во дворе).
- **§ 11. Богатство, выразительность, чистота и уместность речи:** сравнение двух черновиков одной
  заметки — сухого и жаргонного. Финал: из 4 фраз черновиков чистота/уместность нарушена в 2
  (перегружены жаргоном и словами-паразитами).
- **§ 12. Диалог. Монолог, финал раздела:** запись последнего разговора дня и вступительной речи
  Архипа Кузьмича к юбилейному номеру — оформление диалога и монолога на письме. Финал: сцена из
  монолога (1 строка-абзац) и диалога из 4 реплик (4 строки) требует 5 строк записи. Раздел
  «2. Культура устной и письменной речи» пройден полностью (7/7) — переход к разделу
  «3. Речевая ситуация. Стили речи» (герой начинает готовить материалы для разных рубрик газеты).

**Раздел 3 «Речевая ситуация. Стили речи» — герой готовит номер газеты:** Архип Кузьмич поручает
самостоятельные материалы для разных рубрик и учит подбирать стиль под ситуацию.
- **§ 13. Признаки речевой ситуации:** прежде чем писать, герой разбирает реальные сценки редакции
  по четырём признакам (адресант, адресат, цель, обстановка). Финал: из 4 описанных ситуаций
  официальная обстановка — в 2 (объявление на стенде, официальное письмо в администрацию).
- **§ 14. Разговорный, научный и художественный стили речи:** три черновика для разных рубрик —
  дворовая заметка, статья про печатный станок, очерк о здании редакции. Финал: из 4 черновиков
  научным стилем написаны 2 (про отливку литер и температуру плавления свинца).
- **§ 15. Официально-деловой, публицистический стили речи:** сравнение объявления о собрании и
  статьи о судьбе городских архивов. Финал: из 4 черновиков публицистическим стилем написаны 2
  («голос города», обращение «Дорогие читатели»).
- **§ 16. Речевая норма, финал раздела:** финальная проверка готового номера перед печатью на
  соответствие стиля каждой рубрики её ситуации. Финал: из 4 текстов номера стилю ситуации не
  соответствуют 2 (жаргонное объявление, канцелярский художественный очерк). Раздел
  «3. Речевая ситуация. Стили речи» пройден полностью (4/4) — переход к разделу
  «4. Синтаксис и пунктуация» (самый большой этап — восстановление старых статей архива,
  повреждённых пожаром и водой).

**Раздел 4 «Синтаксис и пунктуация» — восстановление статей архива:** Архип Кузьмич вручает герою
ключ от архива, и они начинают разбирать уцелевшие после пожара и воды подшивки — от рассыпавшихся
заголовков до целых статей. Каждый § — свой тип повреждения и свой навык восстановления. Это самый
большой этап (10 тем, § 17-26).
- **§ 17. Словосочетание:** первая папка — вода размыла клей, слова заголовков рассыпались. Герой
  собирает пары «главное + зависимое» и определяет вид связи (согласование, управление,
  примыкание), не путая словосочетание с грамматической основой. Финал: в предложении «Старый
  наборщик аккуратно чинил печатный станок» — 4 словосочетания.
- **§ 18. Виды предложений по цели высказывания и интонации:** заметка об открытии первой
  типографии, вода смыла знаки конца предложений. Герой определяет тип (повествовательное,
  вопросительное, побудительное; восклицательное/невосклицательное) и ставит нужный знак. Финал:
  из 4 восстановленных предложений вопросительных — 2.
- **§ 19. Главные члены предложения:** размытая передовица юбилейного номера — по «скелету»
  (подлежащее + сказуемое) можно достроить размытые слова. Финал: грамматическая основа
  предложения «...сосредоточенный посетитель внимательно изучал старую подшивку» — «посетитель
  изучал», 2 слова.
- **§ 20. Правописание -тся и -ться (орфография внутри синтаксиса):** подпись к старой фотографии,
  чернила расплылись на окончаниях глаголов. Правило «есть мягкий знак в вопросе — есть и в
  глаголе». Финал: из 4 глаголов подписи мягкий знак нужен в 3 (трудиться, готовиться, научиться).
- **§ 21. Правописание личных окончаний глаголов:** колонка новостей с обгоревшими краями,
  сгорели безударные окончания. I/II спряжение, 11 исключений. Финал: из 4 глаголов (писать,
  строить, читать, клеить) ко II спряжению относятся 2 (строить, клеить).
- **§ 22. Второстепенные члены предложения:** почти целое предложение из репортажа — герой
  различает определение, дополнение, обстоятельство, чтобы понять, какие детали смыл дождь. Финал:
  в предложении «Молодой редактор внимательно читал пожелтевшие страницы» — 4 второстепенных члена.
- **§ 23. Однородные члены предложения:** опись спасённого имущества, запятые в перечислениях
  выцвели. Правила запятой (без союза, перед «а»/«но», при повторяющемся «и…и», нет перед
  одиночным «и»). Финал: в предложении «В коробке лежали письма открытки фотографии и вырезки»
  нужно 2 запятые.
- **§ 24. Обращение:** папка писем читателей в редакцию, запятые вокруг обращений смыты. Обращение
  не член предложения, выделяется запятыми. Финал: в предложении «Подскажите, пожалуйста,
  уважаемая редакция, когда выйдет юбилейный номер» обращение в середине требует 2 запятых.
- **§ 25. Строение сложного предложения:** длинный очерк о судьбе города, в каждом предложении по
  несколько событий. Простое/сложное по числу основ, союзная/бессоюзная связь. Финал: в
  предложении «Наступила ночь, редакция затихла, и только в архиве горел свет» — 3 грамматические
  основы.
- **§ 26. Предложения с прямой речью, финал раздела:** последняя находка — неопубликованное
  интервью с основателем «Вечернего вестника». Оформление прямой речи до и после слов автора
  (А: «П». и «П», — а.). Финал: слова автора стоят перед прямой речью, поэтому после них ставится
  двоеточие («Старый редактор торжественно произнёс: „Наш архив снова живёт“»). Раздел
  «4. Синтаксис и пунктуация» пройден полностью (10/10) — переход к разделу «5. Текст» (герою
  предстоит из перепутанных абзацев старых черновиков собрать цельные статьи).

**Раздел 5 «Текст» — разбор коробки перепутанных черновиков:** Архип Кузьмич открывает шкаф с
абзацами без заголовков и дат, оставшимися от нескольких статей сразу; герой учится видеть текст
как целое, а не как случайный набор верных предложений.
- **§ 27. Понятие о тексте:** коробка с перепутанными абзацами старых черновиков — герой отделяет
  абзацы, действительно относящиеся к юбилейному очерку «Редакция возрождается», от случайно
  попавших фрагментов на другую тему (в т.ч. с обманчивым совпадением слова «архив»). Финал: из
  шести найденных абзацев к очерку относятся четыре, два нужно отложить как лишние.
- **§ 28. Основные признаки текста:** четыре восстановленных абзаца, в каждом не хватает своей
  опоры — связности, цельности, завершённости или ясной темы с основной мыслью. Финал: из пяти
  абзацев три уже готовы к печати (все признаки соблюдены), два нужно доработать.
- **§ 29. Виды связи предложений в тексте:** репортажи с цепной связью (местоимения подхватывают
  предыдущее слово) и абзацы-перечисления с параллельной связью (одинаково построенные
  предложения). Финал: в репортаже из шести предложений цепной связью соединены четыре, ещё два —
  параллельно, как перечисление в конце.
- **§ 30. Как строится текст. Повествование, описание, рассуждение, финал раздела:** разбор
  материалов юбилейного номера по типам речи — репортаж-повествование, описание кабинета
  редактора, заметка-рассуждение о ценности архива. Финал: из пяти материалов номера
  повествованием написаны два, значит, три — другого типа (описание и рассуждение). Раздел
  «5. Текст» пройден полностью (4/4) — Архип Кузьмич включает старый радиоприёмник и предлагает
  заняться подготовкой дикторского текста для радиоприложения к газете (переход к разделу
  «6. Фонетика»).

**Раздел 6 «Фонетика» — разминка перед эфиром:** Архип Кузьмич выносит в тесную студию рядом с редакцией старый ламповый приёмник — готовится радиоприложение к газете, а для чтения текста вслух мало уметь писать, нужно понимать звуковое устройство слова. 2 темы.
- **§ 31. Звуки речи и буквы:** различие звука и буквы на примере слова «конь» (4 буквы, 3 звука) и «яблоко» (буква «я» звучит за двоих). Финал: из «конь, весть, стол, вьюга» звуков меньше, чем букв, — в двух словах.
- **§ 32. Гласные и согласные звуки речи, финал раздела:** дикторская разминка — 6 гласных звуков при 10 буквах, пары согласных по звонкости/глухости и твёрдости/мягкости. Финал: из четырёх пар слов только «дом-том» различаются именно звонкостью/глухостью первого согласного. Раздел «6. Фонетика» пройден полностью (2/2) — переход к разделу «7. Фонетика (продолжение)».

**Раздел 7 «Фонетика (продолжение)» — последняя проверка перед печатью:** курс фонетики продолжается тем, как обозначается мягкость на письме, и заканчивается слогами, переносом и ударением. 2 темы (нумерация § снова начинается с 1, как и в остальной части 2 учебника).
- **§ 1. Обозначение мягкости согласных на письме. Двойная роль букв е, ё, ю, я:** рукописный дикторский текст, где буквы е, ё, ю, я то звучат за двоих («ёлка»), то просто смягчают согласного соседа («мёл»). Финал: во фразе «Ёжик ест яблоко» все три гласные буквы в начале слов обозначают по два звука.
- **§ 2. Слог. Правила переноса слов. Ударение, финал раздела:** узкая колонка программы передач требует переносов по слогам, а «зАмок» и «замОк» показывают разноместность русского ударения. Финал: из четырёх слов («майка, улей, ёлка, объезд») вообще нельзя перенести только одно — «улей». Раздел «7. Фонетика (продолжение)» пройден полностью (2/2) — разобрав последние гранки колонки программы передач, Архип Кузьмич признаётся: радиоприложение придётся отложить, в подвале обнаружилась находка поважнее (переход к разделу «8. Орфография»).

**Раздел 8 «Орфография» — самая долгая часть восстановления архива:** Архип Кузьмич откладывает дикторский текст (публикацию радиоприложения решено отложить сразу после раздела «7. Фонетика (продолжение)» — см. его финал выше) и переходит к полкам, сильнее всего пострадавшим от пожара и воды — 15 тем подряд, каждая про свой тип орфографического повреждения.
- **§ 3. Правописание безударных гласных в корне слова:** отсыревшая папка с расплывшимися безударными слогами — нужно различать проверяемые ударением, непроверяемые (словарные) и чередующиеся гласные. Финал: из четырёх слов «вода, трава, собака, звонок» ударением проверяются три — «собака» словарное.
- **§ 4. Правописание согласных в корне слова:** листы с обгоревшими краями — сомнительные согласные на конце корня, включая непроизносимые. Финал: из слов «солнце, поздний, прекрасный, ужасный» скрытая непроизносимая согласная есть только в двух первых.
- **§ 5. Правописание безударных гласных в окончании:** размытые окончания существительных и прилагательных — проверка подстановкой слова того же склонения или вопросом. Финал: из четырёх словосочетаний окончание «-ей» — только у «к дальней станции».
- **§ 6. Правописание гласных и согласных в приставках:** слова, записанные на слух с ошибками — приставки пишутся одинаково независимо от произношения. Финал: из «отдать, оддать, отбежать, оббежать» верно написаны два.
- **§ 7. Правописание букв з и с на конце приставок:** стык приставки и корня, где пожар выжег букву — з или с зависит от глухости/звонкости следующего согласного. Финал: из четырёх слов буква «з» нужна в двух.
- **§ 8. Правописание ы, и после приставок на согласный:** буква и меняется на ы после русских приставок на согласный, но не после сверх-/иноязычных. Финал: из четырёх слов буква «ы» нужна в двух.
- **§ 9. Правописание о, ё после шипящих в корне слова:** проверка чередованием с е, отдельно — слова-исключения без чередования. Финал: из четырёх слов буква «ё» — в двух, «о» (исключения) — в двух.
- **§ 10. Правописание о, ё после шипящих и ц в окончаниях имён существительных и имён прилагательных:** под ударением — о, без ударения — е. Финал: из четырёх слов буква «о» — в трёх.
- **§ 11. Правописание о, ё после шипящих и ц в суффиксах имён существительных и имён прилагательных:** то же правило, но для суффикса. Финал: из четырёх слов буква «о» — в двух.
- **§ 12. Правописание гласных о, а в корнях с чередованием -гор-//-гар-, -зор-//-зар-, -клон-//-клан-:** три родственных, но по-разному устроенных корня. Финал: из четырёх слов буква «о» — в трёх.
- **§ 13. Правописание гласных о, а в корнях с чередованием -лаг-//-лож-, -раст- (-ращ-)//-рос-:** зависимость от следующей буквы или сочетания, плюс слово-исключение «росток». Финал: из четырёх слов буква «о» — в трёх.
- **§ 14. Правописание гласных о, а в корнях с чередованием -кос-//-кас-:** зависимость от суффикса -а- сразу после корня. Финал: из четырёх слов буква «а» — только в одном («касаться»).
- **§ 15. Правописание корней с чередованием гласных е, и:** то же правило суффикса -а-, но для другой группы корней (-бер-/-бир- и т.п.). Финал: из четырёх слов буква «и» — в двух.
- **§ 16. Правописание и, ы после ц:** обычный корень пишется с и, пять слов-исключений — с ы, в окончаниях после ц — тоже ы. Финал: из четырёх слов буква «и» — в двух.
- **§ 17. Правописание буквы ь после шипящих, финал раздела:** правило зависит от части речи и рода — у существительных женского рода и у глаголов ь есть всегда, у существительных мужского рода и кратких прилагательных — никогда. Финал: из четырёх слов («нож, дочь, намажешь, горяч») мягкий знак нужен в двух. Раздел «8. Орфография» пройден полностью (15/15) — Архип Кузьмич переходит к самым старым выпускам архива с устаревшими словами и профессиональным жаргоном наборщиков (переход к разделу «9. Лексика»).

**Раздел 9 «Лексика» — самые старые выпуски архива:** Архип Кузьмич добирается до подшивок, которые старше самой редакции по духу — устаревшие слова, профессиональный жаргон наборщиков и заимствования из моды прошлого века. 8 тем подряд, каждая про свой аспект значения слова.
- **§ 18. Слово и его лексическое значение. Прямое и переносное значения слова:** фельетон со словом «кипела» (о работе, а не о чайнике) — перенос значения по сходству. Финал: из «золотое кольцо, золотая осень, золотые руки, золотой ключ» переносное значение — в двух.
- **§ 19. Однозначные и многозначные слова:** толковый словарь и слово «поле» с четырьмя значениями — контекст подсказывает нужное. Финал: слово «коса» в четырёх вырезках даёт три разных значения (два предложения повторяют одно и то же).
- **§ 20. Синонимы:** объявление и уличный фельетон об одном и том же событии — «сообщаем» и «трепались» как разные по стилю синонимы. Финал: в синонимическом ряду с лишним словом «трусливый» настоящих синонимов — четыре.
- **§ 21. Антонимы:** рубрика «Пословица дня» восстанавливается по принципу противопоставления половин. Финал: из четырёх пар слов настоящих антонимов — три («стол — стул» не антонимы).
- **§ 22. Исконно русские и заимствованные слова:** заметка об открытии телефонной станции и приметы заимствованных слов (буква ф, начальное э, двойные согласные). Финал: из «пальто, сапоги, кофе, рукавицы» заимствованных — два.
- **§ 23. Общеупотребительные слова. Профессиональные слова и термины:** внутренняя переписка редакции с типографским жаргоном («гранки», «кегль», «полоса») — прямая подводка к следующей теме об устаревших словах. Финал: из шести слов профессиональных терминов наборщика — три.
- **§ 24. Устаревшие слова. Неологизмы:** самые нижние подшивки со словами «городовой» и «очи» — историзм (вещь исчезла) против архаизма (слово заменилось). Финал: из шести слов историзмов — три, «смартфон» — не историзм, а неологизм.
- **§ 25. Фразеологические обороты, их отличие от свободных словосочетаний, финал раздела:** фирменные заголовки-каламбуры редакции («Мэрия бьёт баклуши», «Комиссия водит горожан за нос»). Финал: в юбилейном заголовке — два фразеологизма. Раздел «9. Лексика» пройден полностью (8/8) — последняя пачка вырезок разобрана, Архип Кузьмич объявляет о начале подготовки юбилейного номера к печати (переход к разделу «10. Повторение изученного в 5-м классе»).

**Раздел 10 «Повторение изученного в 5-м классе» — юбилейный номер:** финал курса, аналог «Итогового экзамена» математики. Единственная тема «Итоговое повторение» (добавлена через `seed_topic_if_missing`, так как в исходном оглавлении у раздела не было тем) — 10 вопросов, по одному-два из каждого пройденного раздела (1-5, 8, 9; разделы 6-7 «Фонетика» не пройдены и в выборку не входят), и один составной боевой вопрос на три шага (антонимы → историзмы → фразеологизмы), тема — редакция проверяет вёрстку юбилейного номера целиком перед подписанием в печать. Повышенная награда (100/70), как и в математике.

# Академия Великих Исследователей (пилот, 2026-07) — не школьная программа

Отдельный от школьных предметов раздел: ребёнок развивает навыки XXI века (логика,
исследование, инженерия, технологии, творчество, коммуникация, лидерство) вне рамок предметов/
оценок/ДЗ. Сюжет: Академия Великих Исследователей разрушена, семь Кристаллов Разума похищены,
Профессор — единственный, кто остался, — направляет героя по мирам (Мир 1 «Долина Логики», далее

Ораторов», «Великая Экспедиция»), каждый со своим Кристаллом-наградой в конце.

## Техническое решение (важно!)
Полностью переиспользован движок обычных уроков — никакой новой модели данных не вводилось:
- `subject="academy"` — обычная строка в `sections`/`lessons` (backend не валидирует список
  предметов никаким enum, только фронтенд хранит захардкоженные словари подписей/иконок в
  нескольких местах — см. ниже).
- **Мир** = `sections` (`grade=5, subject="academy"`, `title="Мир 1. Долина Логики"` и т.д.).
  Секции без «Глав» — все миссии мира идут единым списком тем внутри секции (движок карты в
  `SubjectPage.jsx` рисует их змейкой узлов, этого достаточно).
- **Миссия/испытание** = `topics` + один `lessons` (`context_theme="castle"`), тот же формат
  LESSON_DICT (`explanation`/`explanation_game`/`questions`/`boss_task`/`coins_*`), что и в
  математике/русском — те же конвенции генерации заданий (сложность нарастает, дистракторы
  правдоподобны, позиции правильных ответов перемешаны, boss_task не повторяет questions[0]).
  Добавляется тем же способом: `seed_section_if_missing` → `seed_section_intro_if_missing` →
  `seed_topic_if_missing` → `seed_lesson_if_missing`, вызовы в конце `init_db()`.
- **Новая визуальная тема `castle`** в `THEMES` (`frontend/src/pages/LessonPage.jsx`) — только
  подписи интерфейса («Испытание №», «Финальное состязание» вместо «Дело раскрыто» и т.п.), плюс
  новый `frontend/src/castle-theme.css`, который переопределяет те же CSS-переменные
  (`--board`/`--paper`/`--ink`/`--dl-gold`/`--dl-navy`/`--font-display` и т.д.), что и
  `.detective-lesson` — сама вёрстка и классы `dl-*` не дублировались, только палитра/шрифт
  (добавлен `Cinzel` в `frontend/index.html`). Корневой класс обёртки в `LessonPage.jsx` теперь
  выбирается по `lesson.context_theme` (`castle-lesson` vs `detective-lesson`).
